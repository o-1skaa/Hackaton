# Интерфейс логиста

React + TypeScript + Vite. Node.js 22.18+ (или 24+) и npm; Python 3.10+ для backend.

## Обновить и открыть сайт вместе с API

В терминале VS Code из корня репозитория остановите старый сервер (Ctrl+C), затем:

```powershell
git pull --ff-only origin main
python start.py
```

Откройте http://127.0.0.1:8000. Скрипт устанавливает зависимости, пересобирает
фронтенд и запускает backend, раздающий сайт. Обновите страницу через Ctrl+F5.
Если Git сообщает о локальных изменениях, сначала сохраните их коммитом или
`git stash push -u`, затем повторите pull. При необходимости верните stash через
`git stash pop` и разрешите конфликты. Не удаляйте локальную работу через reset.

Если порт 8000 занят, остановите прежний сервер в его терминале. Не запускайте
два экземпляра одновременно. После изменений фронтенда единый сервер нужно
остановить и запустить через `python start.py` заново для пересборки.

## Режим разработки: два терминала

После первого совместного запуска, из корня репозитория:

Терминал 1 (Windows PowerShell):

```powershell
cd backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000
```

Терминал 2:

```powershell
cd frontend
npm ci
npm run dev
```

Откройте http://localhost:5173. Vite проксирует `/api`, `/health` и `/openapi.json`
в http://127.0.0.1:8000. При `ECONNREFUSED` сначала запустите backend в терминале 1.
Для отдельного API можно задать `VITE_API_URL` в `.env` и перезапустить Vite.

## Навигация

Сайдбар — единственное меню разделов. Выбранный груз сохраняется при переходах.
Список перевозок служит для выбора груза, поиска и фильтрации.

- **Мониторинг** — этапы, историческая и последняя задержка, документы, маршруты/ETA/CO₂e.
- **AI-прогноз** — ручные условия, прогноз и риск, сведения о модели, ETA до/после расчёта.
- **Источники** — происхождение синтетических сводок и их значения.
- **Документы** — проверка invoice / packing_list и поиск проверки по ID.
- **Журнал** — события выбранного груза.

## Внешний AI-прогноз

Перед запуском настройте `backend/.env` по [общему README](../README.md#подключить-deepseek).
Ключ DeepSeek хранится только на сервере. В браузер передаются состояние настройки и имя модели.
Без ключа кнопка AI-прогноза отключена; остальные разделы работают.

`/api/prediction-context/{id}` загружает сводку выбранного груза и начальные значения
ветра, волн, загрузки порта, погодной оценки и задержки поезда. Их можно изменить
вручную или восстановить кнопкой «Восстановить сводку». Раздел «Источники» показывает
исходные значения и фиксированное время наблюдения. Сбор данных имитируется.

Интерфейс читает OpenAPI и отправляет только объявленные поля. В текущем backend
объявлены все физические параметры и route_id. Ответ содержит задержку, риск,
объяснения, модель, метод, версию промпта, маршрут и ID исходной сводки.

После расчёта повторно загружаются карточка, маршруты и журнал. ETA изменяет сервер
только для выбранного маршрута. При изменении условий старый результат помечается.
Ошибки AI API видны в интерфейсе; локальной подмены прогноза нет.

## Проверки

```sh
npm test
npm run lint
npm run build
```

Тесты проверяют оба контракта прогноза, обязательные поля, валидацию входов и
результатов. Расширенный контракт проверяется фикстурой, а не действующей ML-моделью.
