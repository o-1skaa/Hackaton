# Backend Smart Caspian Transit

Демонстрационный FastAPI backend. Python 3.10+.
Инструкции установки для Windows и Linux/macOS находятся в [общем README](../README.md).

## Запуск и тесты

Все команды выполняются из `backend`, с Python активированного виртуального окружения либо полным путём к его исполняемому файлу.

```sh
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload
```

Для разработки и тестов:

```sh
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

`requirements.txt` содержит зависимости приложения, `requirements-dev.txt` добавляет тестовые инструменты. Диапазоны версий ограничены; полного lock-файла пока нет.

## API

Контракт: [docs/api-contract.md](../docs/api-contract.md).
Swagger при запущенном сервере: http://127.0.0.1:8000/docs.
Модели запросов и ответов находятся в `app/schemas.py`.

CORS разрешает `http://localhost:5173` и `http://127.0.0.1:5173`, методы GET/POST и заголовки Content-Type/X-API-Key.

## Прогноз

`app/services/prediction.py` предоставляет:

- `predict_delay(weather_severity, port_load) -> float` — задержка в часах;
- `predict(weather_severity, port_load) -> dict` — задержка, риск и причины; эту функцию вызывает API.

История: `data/history.csv`. Колонки: `weather_severity`, `port_load`, `actual_delay_hours`.
Для каждой записи вычисляется расстояние `20 * abs(weather - history_weather) + abs(load - history_load)`.
Результат — средняя задержка пяти ближайших записей (или всех, если их меньше пяти), округлённая до десятых.
Факторы погоды и загрузки могут быть дробными в пределах 0–5 и 0–100.
Риск: меньше 2 ч — `low`, от 2 до 4 ч — `medium`, от 4 ч — `high`.
Причины описывают входные факторы; это эвристика, а не оценка вклада признаков.

Это алгоритм на синтетической выборке, без подтверждённой точности на реальных перевозках. Пустая/некорректная история — ошибка данных; перед демонстрацией запускайте тесты. История считывается при каждом прогнозе, поэтому правки CSV применяются без переобучения.

## Маршруты

Расстояния, ETA и CO₂ фиксированные демонстрационные значения, не географический расчёт.
Основной маршрут: 1800 км, `72 + delay` часов, 540 кг CO₂.
Альтернативный: 1950 км, 70 часов, 620 кг CO₂.

Политика выбора: при задержке меньше 5 часов рекомендуется основной маршрут ради меньшего расстояния и CO₂; при задержке от 5 часов — альтернативный ради времени. Поэтому более быстрый маршрут не всегда отмечен рекомендуемым. Объяснение возвращается в `reason`.
До первого прогноза используется задержка 0.

## Данные и ограничения

- Все грузы, история, документы и маршруты демонстрационные.
- Pre-clearance проверяет только наличие типов `invoice` и `packing_list`. Типы нормализуются по регистру и пробелам. Содержимое и подлинность документов не проверяются.
- Событие `submitted` и итог `approved`/`rejected` записываются синхронно.
- Прогнозы, журнал и проверки хранятся в памяти одного процесса и сбрасываются при перезапуске. Запускайте один worker. Для сохранения состояния потребуется отдельное хранилище.
- `DEMO_API_KEY` читается из `backend/.env` или окружения; окружение имеет приоритет. Значение по умолчанию — `demo-local-key`.
- Ключ демонстрационный; его проверка не заменяет авторизацию. Настоящие секреты не должны находиться в браузерном коде.
- `historical_avg_delay_hours` сохраняется в деталях груза для совместимости, но текущий прогноз его не использует.

## Работа команды

Backend отвечает за API, модели и интеграцию. Разработчик прогноза — за `services/prediction.py`, `services/routing.py` и тесты алгоритмов. При изменении сигнатуры функции обновляйте вызывающий код и запускайте API-тесты. Изменения JSON согласовывайте через контракт и Swagger.
