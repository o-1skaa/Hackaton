# Backend Smart Caspian Transit

Демонстрационный FastAPI backend. Python 3.10+.
Инструкции установки для Windows и Linux/macOS находятся в [общем README](../README.md).

## Запуск и тесты

Все команды выполняются из `backend`, с Python активированного виртуального окружения либо полным путём к его исполняемому файлу.

```sh
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload
```

Для разработки и тестов:

```sh
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

`requirements.txt` содержит зависимости приложения, `requirements-dev.txt` добавляет тестовые инструменты. Диапазоны версий ограничены; полного lock-файла пока нет.

## API

Контракт: [docs/api-contract.md](../docs/api-contract.md).
Swagger при запущенном сервере: http://127.0.0.1:8000/docs.
Модели запросов и ответов находятся в `app/schemas.py`.

CORS разрешает `http://localhost:5173` и `http://127.0.0.1:5173`, методы GET/POST и заголовки Content-Type/X-API-Key.

## Прогноз

`app/services/prediction.py` вызывает нативный Gemini REST API:
`https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent`.
Ключ передаётся в заголовке `x-goog-api-key` из `GEMINI_API_KEY`, модель берётся из
`GEMINI_MODEL` (по умолчанию `gemini-3.8-flash`). Используются `systemInstruction`,
`contents` и `generationConfig` с JSON Schema.
Документация: [Gemini structured output](https://ai.google.dev/gemini-api/docs/structured-output).
Настройка: [общий README](../README.md#подключить-gemini).

`POST /api/predict` принимает только `shipment_id` и `route_id`. Любые условия в теле
запрещены (422), включая старые `weather_severity` и `port_load`.
Сервер сам подставляет текущую сводку. Модель получает 200 строк истории, все условия,
выбранный маршрут и данные о происхождении сводки. Собственная модель не обучается,
локального fallback нет. Риск валидируется по порогам <2 / <4 / >=4 ч.

Ответ Gemini разбирается из `candidates[].content.parts[].text`; внутренние thought
части пропускаются. Нужен `finishReason: STOP`. Пустые/заблокированные/оборванные ответы,
невалидный JSON, нечисловая задержка, NaN, выход за 0–720 ч и несовместимый риск
отклоняются. 503 — нет ключа/ошибка провайдера; 504 — тайм-аут; 502 — плохой ответ.
Секрет и сырой ответ провайдера не передаются клиенту. История не содержит физических
или маршрутных признаков; это контекст LLM, метрик реальной точности нет.

## Сводки при запуске

FastAPI lifespan вызывает `services/data_sources.py`. Пул наблюдений находится в
`data/source_observations.json`: 24 различных записи для каждого груза. JSON парсится,
условия валидируются, случайно выбирается запись с другими условиями, чем в прошлом
снимке. Новые `snapshot_id` и время создаются на каждый запуск. Само время означает
момент формирования демо-сводки, не измерения реального метеосервиса.

Снимок атомарно сохраняется в `data/.runtime/source_snapshots.json` и остаётся в памяти
до остановки. Папка исключена из Git. Если файл снимка удалить, исключать условия
предыдущего запуска будет невозможно. Пул исходных наблюдений не изменяется.
Изменения пула применяются после перезапуска. Ошибка данных останавливает запуск;
тихой подмены случайными числами нет. Один worker: каждый процесс имеет свой lifespan.

## Маршруты

Расстояния, базовые ETA и CO₂ — фиксированные демонстрационные значения.
Основной: 1800 км, `72 + main_delay` часов, 540 кг CO₂.
Альтернативный: 1950 км, `70 + alternative_delay` часов, 620 кг CO₂.
Каждый прогноз меняет только задержку выбранного маршрута. Пока для маршрута нет
прогноза, его задержка 0 — это базовый ETA, а не AI-оценка. Сравнение не является
прогнозом обеих альтернатив до их отдельных расчётов.

Основной рекомендуется ради CO₂. Альтернативный рекомендуется, если задержка основного
>=5 ч и альтернативный ETA меньше основного. Эта политика выбора маршрута и сложение
базовой длительности с задержкой остаются обычными вычислениями; величина задержки
поступает только от внешней модели.

## Данные и ограничения

- Все грузы, история, документы и маршруты демонстрационные.
- Pre-clearance проверяет только наличие типов `invoice` и `packing_list`. Типы нормализуются по регистру и пробелам. Содержимое и подлинность документов не проверяются.
- Событие `submitted` и итог `approved`/`rejected` записываются синхронно.
- Прогнозы, журнал и проверки хранятся в памяти одного процесса и сбрасываются при перезапуске. Запускайте один worker. Для сохранения состояния потребуется отдельное хранилище.
- `DEMO_API_KEY` читается из `backend/.env` или окружения; окружение имеет приоритет. Значение по умолчанию — `demo-local-key`.
- Ключ демонстрационный; его проверка не заменяет авторизацию. Настоящие секреты не должны находиться в браузерном коде.
- `historical_avg_delay_hours` сохраняется в деталях груза для совместимости, но текущий прогноз его не использует.

## Работа команды

Backend отвечает за API, модели и интеграцию. Разработчик прогноза — за `services/prediction.py`, `services/routing.py` и тесты алгоритмов. При изменении сигнатуры функции обновляйте вызывающий код и запускайте API-тесты. Изменения JSON согласовывайте через контракт и Swagger.
