# Smart Caspian Transit

Демонстрационный MVP для кейса №2 IV Каспийского цифрового форума 2026.
React + TypeScript + Vite и FastAPI в одном репозитории.
Все данные синтетические, реальных таможенных, погодных и GPS-интеграций нет.

## Открыть готовый сайт с бэкендом

Нужны Python 3.10+ и Node.js 22.18+ с npm. В терминале VS Code из корня:

```sh
git pull --ff-only origin main
# Перед первым запуском: настройте backend/.env (см. ниже)
python start.py
```

На macOS/Linux, если `python` отсутствует: `python3 start.py`.
Скрипт создаёт `backend/.venv`, устанавливает зависимости Python и npm,
собирает фронтенд и запускает единый сервер.
Откройте **http://127.0.0.1:8000**. Остановка: Ctrl+C.
Первый запуск требует интернета. Порт 8000 должен быть свободен.
После изменений UI снова запустите скрипт для пересборки.

## Подключить DeepSeek

Остановите прежний сервер (Ctrl+C). В корне проекта один раз выполните в PowerShell:

```powershell
Copy-Item backend/.env.example backend/.env
```

Если `backend/.env` уже есть, сохраните его и добавьте строки вручную.
Откройте `backend/.env` в VS Code и заполните:

```dotenv
DEMO_API_KEY=demo-local-key
DEEPSEEK_API_KEY=ваш_ключ_DeepSeek
DEEPSEEK_MODEL=deepseek-flash
```

Ключ создаётся на https://platform.deepseek.com; нужен доступ к API и достаточный баланс.
После этого запустите `python start.py` и откройте http://127.0.0.1:8000.
Ключ читается только backend, файл `.env` исключён из Git. Не используйте `VITE_` для ключа.
Имя модели настраивается через `DEEPSEEK_MODEL` под доступные вашему аккаунту модели.

Прогноз — вызов готовой внешней языковой модели DeepSeek, не собственная обученная
регрессия и не локальная формула. Она получает 200 исторических синтетических наблюдений,
сводку условий и выбранный маршрут. Ответ содержит задержку, риск, причины и сведения
о модели. Собственная нейросеть не создаётся и не обучается.

Без ключа мониторинг, сводки, документы и журнал работают; AI-прогноз отключён.
При ошибке API возвращается явная ошибка без подмены формулой, ETA и события не меняются.
Сетевой тайм-аут — 45 секунд на операцию чтения, подключения — 10 секунд.
Каждое нажатие расчёта отправляет платный запрос провайдеру.

## Интерфейс

- Поиск и фильтрация перевозок, карточка и этапы доставки.
- Единая навигация в сайдбаре: мониторинг, AI-прогноз, источники, документы и журнал.
- Прогноз задержки и риска; учитываются поля ветра, волн, задержки поезда и маршрута.
- Проверка контракта API: неподдерживаемые сервером параметры отключены.
- Метод/версия модели при наличии в ответе; сравнение ETA до/после расчёта.
- Сравнение основного и альтернативного маршрутов: ETA, расстояние, CO₂e.
- Проверка комплектности invoice / packing_list, поиск результата по ID.
- Журнал событий, обновление данных, состояния загрузки и ошибок.

Сайт обращается к настоящим API текущего бэкенда, без подмены данных в браузере.
В проверке документов отправляются только типы и имена файлов, содержимое не загружается.
Локальный демонстрационный ключ: `demo-local-key`; если в `backend/.env` задан
другой `DEMO_API_KEY`, введите его в поле раздела «Документы».
Ключ демонстрационный, это не система авторизации для production.
Состояние прогнозов, проверок и событий хранится в памяти и сбрасывается после перезапуска.

Сводки из `backend/data/source_snapshots.json` имитируют результаты сбора метеоданных,
загрузки порта и железнодорожных сообщений. Они фиксированные и явно помечены как
синтетические. История содержит только погодную оценку, загрузку порта и задержку;
реальных корреляций физических параметров или метрик точности мы не заявляем.
Это демонстрация интеграции AI API; точность прогноза на реальных перевозках не проверена.

## Разработка: два терминала

Бэкенд из `backend/` (после создания окружения командой выше):

Windows PowerShell:
```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

macOS/Linux:
```sh
.venv/bin/python -m uvicorn app.main:app --reload
```

Фронтенд из `frontend/`:
```sh
npm ci
npm run dev
```

Откройте http://localhost:5173. Vite проксирует `/api` и `/health` в бэкенд.
Для другого адреса API используйте `frontend/.env` по `.env.example`;
при работе на разных origins понадобится соответствующий CORS на сервере.

## Проверки

```sh
cd frontend
npm ci
npm run build
npm run lint
npm test
```

Из `backend/`, с Python своего окружения:
```sh
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

## Структура

- `frontend/src/` — интерфейс и типизированный API-клиент.
- `start.py` — совместный запуск сайта и API.
- `backend/app/main.py` — FastAPI, демо-проверки, события и раздача собранного сайта.
- `backend/app/schemas.py` — авторитетные модели запросов и ответов.
- `backend/app/services/` — прогноз и выбор маршрута.
- `backend/data/` — четыре синтетических груза и история задержек.
- `backend/tests/` — API, алгоритмы и интеграция сайта.
- `docs/api-contract.md` — API-контракт; Swagger: http://127.0.0.1:8000/docs.

Если фронтенд ещё не собран, `/` возвращает инструкцию с кодом 503; API доступен отдельно.
Подробности алгоритмов: [backend/README.md](backend/README.md).
